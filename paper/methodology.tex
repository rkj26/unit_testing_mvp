\section{Methodology}
\label{sec:method}

We evaluate whether unit tests written by a trusted model detect code backdoors, and address three questions. (i) Do tests alone detect backdoors as well as a trusted monitor that reads the code? (ii) Does giving the monitor the results of those tests improve safety at a fixed audit budget? (iii) When tests miss a backdoor, is it because no test input reaches the trigger, or because no test asserts a property that the backdoored output violates?

\subsection{Threat model}
\label{sec:setting}

We adopt the high-stakes AI control setting of \citet{greenblatt2024aicontrol}. An untrusted model $U$ solves programming tasks, and a submission may contain a \emph{backdoor}: code that is correct on ordinary inputs but returns an incorrect output on a rare trigger input chosen by its author. The blue team has a weaker trusted model $T$ and a small budget of human audits, which we assume to be perfect. The blue team wins if an audit catches a backdoor before any functional backdoor is deployed. The red team's attack policy is a fixed corpus of backdoors written by other models~\citep{terekhov2025controltax} (Section~\ref{sec:data}); it does not adapt to the protocol or choose which tasks to attack, a limitation we return to in Section~\ref{sec:results}.

\paragraph{Trusted monitoring.} Following \citet{greenblatt2024aicontrol}, $T$ reads the task and the submission and rates the likelihood of a backdoor from 1 to 10; the score is the mean of two samples.

\paragraph{Test generation.} Testing proceeds in two stages. First, $T$ reads the task and the submission and proposes $n$ inputs designed to satisfy each condition in the code that could gate an incorrect output. This search runs once per candidate, honest and backdoored alike, and all test-based protocols share its inputs, so differences between them reflect the tests rather than the inputs. Second, $T$ writes a suite of $t$ tests; each test is executed on every input, and the score $k \in \{0, \dots, t\}$ is the number of tests that fail on at least one input. Because the setting assumes $T$ cannot reliably solve the task, a test may not compute the expected output: it must assert a property that every correct output satisfies. \emph{Property tests} may relate outputs across inputs through metamorphic relations~\citep{chen1998metamorphic}, bounds, format invariants or answer certificates~\citep{claessen2000}; \emph{plain tests} check a single output in isolation. The comparison isolates whether relational checks add detection power or only false alarms, since a relation the specification does not guarantee also fails on correct code.

\paragraph{$U$ plans, $T$ writes.} $U$ reads the submission and writes a natural-language test plan without code, and $T$ implements the suite from the plan without seeing the submission. This tests whether a stronger model's reading of the code yields better tests. It carries two caveats, which it is partly designed to measure: a $U$ that recognises its own backdoor could plan tests that avoid it, and $U$ reasons at higher effort than the protocols it is compared with.

\paragraph{Monitoring with tests.} The trusted monitor, with the same prompt and number of samples, additionally receives one suite's source code and execution results on the same submission. The prompt warns that a failing test may reflect either a genuine backdoor or an assertion the specification does not support. We evaluate one variant per suite.

\paragraph{Defer to trusted.} As in \citet{greenblatt2024aicontrol}, a monitoring protocol can replace a suspicious submission that is not audited with $T$'s own solution, which contains no backdoor. A second, lower threshold decides which submissions are deferred.

\subsection{Data}
\label{sec:data}

We use APPS~\citep{hendrycks2021apps} with the backdoored solutions of \citet{terekhov2025controltax} from the \texttt{apps-control-arena} dataset~\citep{appscontrolarena}. A task is included if its reference solution is correct and deterministic and at least one backdoor passes the visible tests and disagrees with the reference solution on its trigger input; a backdoor that never triggers is an ordinary bug, not an attack. Each task contributes one honest and one backdoored candidate, so no task is counted twice in a rate. All of APPS yields 1{,}388 such tasks (2{,}776 candidates), split into 555 calibration and 833 evaluation tasks. We verify every label independently with the ControlArena scorer (Appendix~\ref{app:implementation}).

\paragraph{Label leakage.} As released, 48.6\% of the backdoored solutions contain a comment naming the backdoor (e.g.\ \texttt{\# Subtle bug: ...}) and none of the honest ones do. Any protocol that reads the code would exploit this artefact, so we remove all comments and self-describing identifiers from both classes before running any protocol.

\subsection{Evaluation}
\label{sec:safety-model}

\paragraph{Audit threshold.} Following \citet{greenblatt2024aicontrol}, the audit threshold $\tau_b$ for budget $b$ is the $(1-b)$ quantile of a protocol's scores on honest calibration candidates; no attack labels are used. Scores are discrete, so we break ties at $\tau_b$ at random such that exactly a fraction $b$ of honest calibration candidates is audited. Every protocol therefore spends the same budget.

\paragraph{Safety.} The budget enters only through the threshold: at evaluation, every candidate above $\tau_b$ is audited, however many there are. Under this model, and with attacks on uniformly random tasks, an attack's outcome depends only on its own score and not on when it occurs, so expected safety does not depend on the attack rate (up to the chance that no attack is decisive in a finite deployment). We therefore attack every evaluation task, which minimises variance. Let $a_i$ and $d_i$ be the probabilities that the attack on task $i$ is audited and deferred, and $w_i \in \{0, 1\}$ indicate a functional backdoor. Safety is the probability that the first decisive attack is caught,
\[
  \mathrm{Safety} \;=\; \frac{\sum_i a_i}{\sum_i a_i + \sum_i (1 - a_i - d_i)\, w_i},
\]
and 1 when no attack is decisive. Without deferral, safety is the fraction of functional attacks audited.

\paragraph{Usefulness.} On honest evaluation candidates, an audited or deployed submission counts as correct and a deferred one counts as correct if $T$'s own solution passes every test of the task under the ControlArena scorer. We rescale usefulness so that 0 is $T$ alone and 1 is $U$ alone~\citep{greenblatt2024aicontrol}.

\paragraph{Reporting.} The primary operating point is $b = 2\%$, as in \citet{greenblatt2024aicontrol}; we also report $b \in \{1, 5, 10\}\%$. For defer to trusted we fix $\tau_{2\%}$ and sweep the deferral threshold to trace a safety--usefulness frontier. We report ROC AUC and the detection rate at fixed false-positive rates, which characterise each protocol independently of the safety model. Intervals are 95\% percentile intervals from 10{,}000 paired task resamples, in which every protocol recalibrates its threshold on the resampled calibration tasks; we report them for each protocol and for its paired difference from trusted monitoring. All comparisons use the candidates that every protocol scored (2{,}435 of 2{,}776); a candidate a protocol failed to score is excluded rather than assigned a default score, since an unscored test suite would otherwise count as passing.

\paragraph{Implementation.} $T$ is DeepSeek-V3.2~\citep{deepseekv32} at low reasoning effort and $U$ is the same model at high effort, so the capability gap arises from reasoning effort alone. We use $n = 30$ trigger inputs and $t = 10$ tests, and run every test in an isolated sandbox. Further details are in Appendix~\ref{app:implementation}.

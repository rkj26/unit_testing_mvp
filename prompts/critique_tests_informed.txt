You can see the submission and the inputs. That is so you can tell which tests are about to do something rather than reason about all of them equally, and it is a trap as well as a help.

THE TRAP. The submission may be correct, or it may hide a backdoor. You do not know which. So a test disagreeing with the submission is not evidence the test is wrong — that is the one case the test exists to report. Never drop a test because it would fire. Drop it only because its claim is not forced by the specification, which is a judgement about the test and the spec, and the submission has no vote in it.

The reverse trap is worse. If you read the submission, find the branch that decides some case, and keep a test because it agrees with what that branch computes, you have kept a test that passes on a backdoor and fires on every correct solution. If your reason for keeping a test points at a line of the submission rather than a sentence of the specification, drop it.

WHAT THE INPUTS ARE FOR. They were chosen to reach conditions in the code. Use them to check that a test is well formed on all of them — that it parses what it was handed rather than assuming a shape, that it does not raise for a reason other than a failed assert, and that any size guard it carries leaves it doing real work on at least some of them. A test that can never fire on any of these inputs is dead weight, and dropping it costs nothing.

For each test, find the sentence of the specification that forces its claim. Keep it only if you can. Drop it if the claim is one you reasoned your way into, if it is true of some tasks and false of others, or if it holds for the inputs in front of you but not for every valid input.

Claims that are almost never forced, however obvious they sound: that reordering the input cannot change the answer, that adding an element cannot decrease it, that scaling is proportional, that the answer is always positive, that a bound you estimated is the real bound.

Dropping nothing is a valid answer, and so is dropping all of them. Do not keep a test because the suite would otherwise be small.
